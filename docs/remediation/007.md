# MDPS-AUDIT2-007: representation restart and unavailable states

A representation marked `running` is a lease owned by the Archive operation
that held the synchronization lock. After that lock has been freshly acquired by
a later operation, no prior worker can still own the lease. Initialization then
atomically changes stale `running` representations to `interrupted`.

Restart recovery preserves the recorded path, origin, verification timestamp and
prior error. It appends explicit restart provenance instead of discarding
historical evidence. Nested same-thread operations that join an already-held
Archive lock do not perform restart recovery, so a live worker cannot be
reclassified merely because another component initializes the Store.

For a missing or non-complete representation whose source is known to be
deleted, private or otherwise unavailable, synchronization persists
`blocked_unavailable`. It does not invoke the downloader. The existing path and
error evidence is retained and the blocking reason is appended. If later
discovery shows the source as public again, the ordinary synchronization path
can move `blocked_unavailable` through `running` to `complete`.

The GUI no longer filters unavailable missing items before the state machine sees
them. They are counted as attempted work, reach `MediaExecutor::syncItem`, and
produce durable blocking state plus an operator-visible failure requiring
external recovery.

Regression coverage includes a live nested-lock case, fresh-restart recovery,
evidence preservation, unavailable video/audio blocking without downloader
execution, and retry from blocked state to complete.
