# MDPS-AUDIT2-012: missing-registry admission

A root with both registries missing is not necessarily a new archive. The
initializer now checks for payloads, hidden entries, unexpected directories,
recovery packages, logs and generated root evidence before creating empty state.
Only the exact empty structural layout and the current held lock are exempt.
Existing evidence is never removed or adopted during this check.

Fresh archives get an `archive-identity.json` marker in the same journaled
transaction as their first two registries. The marker identifies the format,
version, random archive ID, admission timestamp and admission origin. It is not a
cryptographic attestation of media identity. The normal roll-forward machinery
recovers interrupted initialization without generating a different identity.

Recognized unversioned archives with both valid registry arrays gain a marker
transactionally without reserializing either registry or historical occurrences.
Unknown or corrupt marker versions fail closed. Missing registries beside old
archive evidence require restoration from a known-good backup, not an empty
reset. An independent, explicitly selected empty root can be used for a new
archive. Existing archive media, notes and recovery evidence remain in place.

Root identity is not tied to an absolute path, so moving a complete archive does
not invalidate it. Existing link/reparse checks remain in force. This change does
not claim to fix separate canonical graph, full-field schema, provenance or
per-playlist state-loss findings.

## Verification

New orphan-data, identity-lifecycle and legacy-admission tests failed on the
unchanged integration production source before the correction. The added tests
cover Video, Audio, Metadata, State, Temp, hidden media, Pending/Accepted/Rejected
recovery evidence, historical logs, empty historical subdirectories, root
resources, genuinely empty layout, unrelated user notes, idempotent restart,
valid legacy migration, one/both missing registries and unsupported markers.
A fourth test stages a durable initialization journal with only the marker
already replaced, then checks exact, idempotent restart recovery.

Local, CI, commit and integration outcomes are recorded in issue #3. Historical
audit evidence and the immutable baseline are not modified by this remediation.

The existing media-integrity fixture previously copied its corrupt canonical
media before initializing its registries. Its setup now explicitly initializes
the empty root first. All original verification, corruption rejection and residue
assertions are unchanged. The new orphan-data case separately requires the old
unsafe admission sequence to fail. This is an intentional admission-contract
change, not suppression of an integrity-test failure.

Executed local qualification: full clean-configured Debug build and all 32
CTest cases pass. The same 32 cases pass under AddressSanitizer and
UndefinedBehaviorSanitizer with leak detection and halt-on-error enabled.
GitHub Windows/PR qualification and combined integration remain separate gates.
