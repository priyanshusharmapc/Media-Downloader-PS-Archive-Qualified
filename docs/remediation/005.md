# MDPS-AUDIT2-005: sealed runtime tool resolution

Archive Mode treats its bundled external executables as part of the qualified
runtime boundary. Default `RuntimeConfig` therefore resolves yt-dlp, FFmpeg,
FFprobe and Deno only from the known package-relative locations. Candidate paths
must be ordinary executable files and must not traverse linked path components.

If a required bundled executable is missing, renamed, quarantined or replaced by
a link, resolution fails closed. A same-named executable on the process
`PATH` is not used as a substitute.

Development builds that intentionally need system-installed tools can set
`RuntimeConfig::allowSystemTools=true`. This is an explicit caller decision
and is outside the qualified portable execution policy. Production Archive GUI
and CLI construction use the default sealed policy.

Regression coverage places a functioning substitute on `PATH` and verifies
that sealed mode refuses it, while explicit development mode can resolve it.
The real CLI integration suite also keeps real FFmpeg/FFprobe on `PATH`,
removes a bundled executable, and verifies Archive synchronization fails instead
of escaping the package boundary.
