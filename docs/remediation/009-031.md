# Discovery admission: MDPS-AUDIT2-009 and MDPS-AUDIT2-031

Base: `8a62c9b2c5d63f4f9c1cfa6373884e37bf1348c1` on `audit2-remediation`.
Frozen forensic baseline: `b53457008af9af7716e4745bdd2812458e95766f`.
Claim: issue #3 comment `5738251655`. Historical findings are not edited.

## Corrected invariants

009 (High): the requested source key is not proof of provider identity. A missing,
empty, incorrectly typed or mismatched root playlist ID is now an explicitly
refused observation. It neither inserts wrong-source memberships nor authorizes
removals. A matching provider ID remains eligible for a complete snapshot,
including an actually empty playlist that legitimately removes old occurrences.

031 (Medium): a present `playlist_index` must be a finite, integral positive JSON
number within the supported integer range. Wrong types, nulls, fractions, zero,
negative and overflowing values are not silently replaced by array order.
Contradictory positions make a snapshot partial, so absence is not removal
proof. Completely absent indexes retain the deterministic one-based array-order
fallback. Repeated videos at distinct positions remain supported occurrences.

The parser continues to retain attributable positive observations from partial
snapshots, except entries with invalid indexes. Existing process, count, warning
and transient-failure guards remain in force. This change does not resolve 044's
separate media scheduling behavior on warning-bearing partial snapshots.

## User-visible behavior

Suspect extractor responses now report an incomplete-discovery or identity error.
Existing playlist history and active membership are retained; the operator can
retry discovery after correcting the source or extractor response. Neither
historical media nor state is deleted to make a malformed snapshot acceptable.
No migration of already valid archives is required.

## Executable evidence

Three new hardening cases fail against unchanged production source before the
fix: `archive-discovery-root-identity`, `archive-discovery-explicit-index` and
`archive-discovery-position-uniqueness`. These use real Store reconciliation to
check that suspect discovery cannot remove historical membership. The root case
also checks refusal of wrong-source additions and successful legitimate removal.

The full local Linux Debug suite contains 31 cases, including all existing tests.
The same suite is run with AddressSanitizer and UndefinedBehaviorSanitizer,
leak detection and halt-on-error. Final actual results, commit, PR and GitHub
qualification belong in issue #3; local success alone is not integration evidence.

The pre-existing nonzero-exit fixture now includes its intended playlist ID.
Its assertions that observed entries survive, completion is false, and the
removal-safety diagnostic is present are unchanged. The initial run with the
old unbound fixture failed and was retained; new identity cases explicitly
assert refusal of that old missing-ID input. This is an input-contract fixture
correction, not removal of partial-observation behavior or weaker assertions.

Cross-finding review also strengthened the existing null-entry, count-mismatch
and process-error fixtures with matching provider IDs and paired valid controls.
Their original failure assertions remain; the added checks prevent the new
identity gate from masking those independent historical safety guards.
