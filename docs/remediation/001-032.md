# MDPS-AUDIT2-001 and MDPS-AUDIT2-032: root admission and selection

## Scope and historical identity

Base: `8a62c9b2c5d63f4f9c1cfa6373884e37bf1348c1` on `audit2-remediation`.
Frozen discovery baseline: `b53457008af9af7716e4745bdd2812458e95766f`.

001 is High severity: unavailable configured roots were replaced by inferred roots,
and unconfigured GUI launch could initialize an unintended archive.
032 is Medium severity: an explicit rejected candidate replaced the accepted setting.
They are distinct findings sharing the GUI root-admission boundary, not duplicate IDs.

## Fix and feature preservation

Root resolution preserves explicit configuration and no longer infers a root.
GUI reads, actions, worker entry, and health refreshes check availability before
calling Store operations that may create layout. Browse remains available for
recovery. Root selection validates the candidate and durably commits its setting
before switching the active root. Settings failures preserve old bytes and cannot
be retried implicitly by a QSettings destructor. The existing core, downloaders,
archive contents, recovery operations, and CLI initialization remain in place.

The Archive page now has a host-tab constructor, while the existing Context
constructor remains as its production adapter with the same main-widget ownership.
This permits execution of actual widget lifecycle behavior without starting any
ordinary downloader engines or external network operations in the test harness.

## Executable regression evidence

The unchanged integration base built successfully and passed all 28 Linux CTest
cases before production edits.

Four new root-resolution cases were run against the unchanged production settings
implementation and failed: offline absolute root, unconfigured generic folders,
offline legacy root, and empty explicit root precedence. The existing package-
independent settings case still passed. The same cases pass with the correction.

For 032, an isolated mutation of the corrected selection helper restored the
frozen assign/persist/validate ordering. Four tests then failed: corrupt candidate,
linked candidate, conflicting settings writer, and unusable settings destination.
This is an explicit old-order mutation test, not a claim that the new helper API
existed in the untouched historical baseline. The mutant is not shipped.

The existing `archive-gui-settings-tests` executable now contains 14 named cases,
including actual Archive widgets, and all pass locally. Full Linux CTest: 28/28.
AddressSanitizer plus UndefinedBehaviorSanitizer with leak detection and halt-on-
error enabled: 28/28. No test or sanitizer assertion was weakened or skipped.

The test environment is Debian 13, Qt 6.8.2, Debug configuration. GitHub Actions
must provide separate Windows and integrated-commit evidence. The CI push filter
now includes `audit2-remediation`, without dropping any existing trigger.

## Windows qualification correction

PR run `35412391864` passed Linux including sanitizers, but the Windows job
`105814418902` correctly failed `archive-gui-settings`: private INI serialization
failed while the other 28 Windows tests passed. This was a product regression,
not a flaky runner failure. Qt 6.8.1's QTemporaryFile engine keeps the native file
handle after close(), without Windows delete sharing; QSettings could not perform
its atomic replacement of that staged path.

The follow-up uses a regular QFile in an owned QTemporaryDir and lets its actual
handle close before QSettings opens the snapshot. The live-file writer lock,
private-cache isolation, corruption checks, atomic final QSaveFile commit and
all 14 settings/widget cases remain unchanged. Windows qualification must be
rerun and pass before integration. The failed run remains part of the evidence.
